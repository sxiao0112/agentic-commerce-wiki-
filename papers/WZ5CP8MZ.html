WebMall

A reproducible test of whether a web agent can search, compare, and buy products across four different simulated shops.

Peeters et al.arXiv:2508.13024v22 December 2025Technical report

Abstract and version record · PDF · Code and data · Project page

Version boundary. This card reports arXiv v2 only. ArXiv lists v3 dated 30 April 2026, and the live project page now shows additional models and 16 setups. Those later results are outside this card. The v2 paper tests eight setups based on GPT‑4.1 and Claude Sonnet 4.

Research question

Can a fixed, offline environment measure how well web agents complete long comparison-shopping journeys across several heterogeneous shops? Within that environment, how do three agent choices affect effectiveness and efficiency: page representation, short-term memory, and language model?

Terms used on this page

AX-Tree
The browser accessibility tree. It exposes page structure, controls, and labels as text.
Vision
A screenshot with numbered marks that connect visible elements to accessibility-tree IDs.
Short-term memory
A persistent note area that the agent can update between browser steps.

What the benchmark tests

4
simulated shops

Four locally hosted WooCommerce shops use different templates, visual designs, and category trees. Each shop has search, product pages, a cart, and checkout.

4,421
product offers

Offers come from the October 2024 Web Data Commons extraction of Common Crawl. The authors keep English offers with title, description, price, and currency, remove exact duplicates, and cluster offers with GTIN or MPN identifiers.

91
tasks

Eleven categories form five groups. The tasks cover cross-shop search, price comparison, cart actions, checkout, substitutes, and compatible products.

50
maximum steps per run

A step is an AgentLab browser action such as going to a page, clicking, filling text, or scrolling.

Exact experiment

Two model backends

  • GPT‑4.1: gpt-4.1-2025-04-14
  • Claude Sonnet 4: claude-sonnet-4-20250514

Four observation setups per model

  1. AX-Tree
  2. AX-Tree + memory
  3. AX-Tree + vision
  4. Vision only

Two models × four setups = eight baseline agents. The paper does not test a vision-plus-memory setup.

Shared protocol

All eight agents use BrowserGym and AgentLab, the same 91 tasks, the same four shops, and the same 50-step cap. No human baseline, random baseline, repeated-run variance, confidence interval, or statistical significance test is reported in v2.

The paper states the per-task macro averaging rule. It does not document special handling for a zero precision or recall denominator.

Supported findings

Structure is the strongest common signal

Every task group’s best setup uses the AX-Tree. Vision-only agents are weaker. Both vision-only models score 0% CR on the eight end-to-end tasks. Claude vision-only also scores 0% CR on the 15 action and transaction tasks.

Memory helps selected workflows

GPT‑4.1 AX-Tree + memory reaches 100% CR on the 15 action and transaction tasks. Claude AX-Tree + memory reaches 75% CR and 84.26% F1 on the eight end-to-end tasks. Memory reduces mean steps for each model, but increases total token use.

Search remains hard

The best group-level CR is 54.44% for cheapest search (Claude, AX-Tree) and 53.61% for vague search (Claude, AX-Tree). These denominators are 26 and 19 tasks. Partial-credit F1 is 60.29% and 70.16%.

Failure is often procedural

Observed errors include stopping after one shop, using a rigid query, misreading attributes, clicking the wrong control, and submitting malformed URLs. These failures can reduce the score even when some product reasoning is correct.

What this paper uniquely adds

WebMall turns comparison shopping into a controlled web-agent problem. Its main contribution is the combination of four independently styled shops, heterogeneous offers collected from many real sites, cross-shop answer sets, and executable cart and checkout actions. This design exposes a failure mode that a single-store benchmark can hide: an agent can find one plausible item and still fail because it did not search and aggregate across every shop.

Limits on interpretation

  • The environment is reproducible, but it covers four simulated WooCommerce shops and three electronics categories. Results do not establish performance on the live Web or in other retail domains.
  • The authors manually select and distribute task-relevant offers. They use GPT‑4.1, embeddings, and manual constraints to add other catalog offers. The resulting task set is curated, not a random sample of shopping requests.
  • There are 91 tasks, including only 5–12 tasks in each category. The paper reports one result per setup without run-to-run variance or statistical tests.
  • Exact-match CR treats an extra URL, a missed URL, or a malformed submission as failure. Precision, recall, and F1 show partial progress, but the benchmark does not score user satisfaction or product quality beyond its stored solutions.
  • The eight baselines vary several coupled implementation choices across two proprietary model APIs. Their results establish baseline difficulty; they do not isolate causal effects or rank all possible agents.
