ShopperBench

Can a shopping agent finish a product search and also act like the shopper it represents? ShopperBench tests that question with persona-conditioned WebShop tasks and trajectory-level judgments.

Ling et al.March 2026Pages 837–846240 tasks10 personas DOI ACL record Full paper (PDF)
QuestionSetupExperimentMetricsResultsLimits

What the paper adds

Persona alignment for an entire shopping path

The benchmark scores search queries, tool actions, and the final choice. It separates task completion from three kinds of persona alignment. This is the paper’s distinct contribution.

Main result

More persona guidance gives small alignment gains and longer paths

Persona-Constrained has the best three persona scores. Task-Focused has the best task success and the shortest agent median path. See §5.1 and Table 1.

Research question

Does explicit persona guidance change how an agent shops?

Operational question. Can one base language model adapt its search and purchase strategy to a shopper persona, and what happens to task success and interaction length when persona guidance becomes stricter?

Supported by the paper’s stated experiment goals in §5, page 840.

Task and data

One episode joins a persona, a request, goals, and a store state

A persona is a short profile of shopping behavior. A goal facet is a structured product attribute, constraint, or preference.

Episode

(p, I, G, E)

p: persona profile
I: natural-language instruction
G: structured goal facets
E: catalog, item metadata, and page context

Scale

240 persona-conditioned tasks from 60 human-created WebShop query clusters.

Environment

A user simulator and a ShopperAgent interact through the τ²-Bench style loop. The agent can search, open a product, apply filters, and add an item to the cart.

Definitions: §3.1, dataset composition: §3.3, interaction: §4.1.

Construction flow

  1. Sample a source taskSelect a WebShop query cluster, representative query, persona, and instruction.Input: c, q, p, I
  2. Extract goal facetsParse the instruction and product metadata into attributes, constraints, and relevant preferences.Output: initial G
  3. Inject the personaKeep persona-relevant constraints and remove inconsistent ones. Rewrite the instruction without changing the original product intent.Output: refined I′ and persona-aware G
  4. Create evaluation assertionsGenerate natural-language checks for task success, persona fidelity, query alignment, and path consistency.Output: task specification T = (I′, G, A)
  5. Convert the human pathMap the WebShop human trajectory to the agent tool interface. This becomes the oracle human trajectory.Tools include search_products, open_product, and add_to_cart
  6. Run one policy in the dual-agent loopThe user simulator gives persona-conditioned cues. The ShopperAgent responds or makes one tool call. The loop continues to a cart decision.Policies: TF, PA, or PC
  7. Score outcome and pathReport task success plus three persona-alignment scores. Compare interaction steps with the oracle human paths.Aggregate over persona task counts

Exact experiment

One base model, three prompt policies

All policies use Claude Haiku 4.5. The paper says the policies differ in how they receive persona information.

Compared policies
PolicyInputs stated in §4.2Role in the comparison
Task-Focused (TF)Instruction I and goal facets G; no persona signalPersona-agnostic control that aims to find the product in few steps
Persona-Adaptive (PA)Persona card, refined instruction I′, and persona-conditioned G; no procedural rulesTests whether the model can internalize persona cues
Persona-Constrained (PC)Same inputs as PA, plus persona-specific operational rulesTests explicit rules that shape tool choice and trajectory planning

The available tools are search_products, open_product, apply_filters, and add_to_cart. The paper does not compare another model, a retrieval method, or a learned personalization method.

Policy definitions: §4.2. Base model: §5. Prompt frameworks: Appendix B.

Metrics and denominators

The paper defines what each score means, but not how the judge computes it

Task Success Rate (TSR)
Whether the correct item, or an acceptable equivalent, is added to the cart.
Persona Fidelity Score (PFS)
A judge LLM assesses whether actions and tool calls match persona behavior. This concerns behavior, not wording.
Persona–Query Alignment (PQA)
The judge assesses whether the interpretation and search queries match the persona.
Path Consistency (PC)
The judge assesses whether the full trajectory agrees with the persona and the final purchase.

Aggregation that can be verified

The Appendix gives a score Mp and task count np for each persona. Each Table 1 value is the task-count-weighted mean:

M overall = (Σp np × Mp) / (Σp np) = (Σp np × Mp) / 240

Example: this calculation gives TF TSR = 0.6402, which Table 1 rounds to 0.640. It also reproduces the other eleven headline values.

Missing measurement detail. The paper gives no explicit primitive formula for PFS, PQA, or PC. It does not name the judge model, show the judge prompt, define the score scale, state the number of trials, or report seeds. It also does not define “acceptable equivalent.” Some persona TSR values cannot result from one binary observation per listed task. For example, 0.583 with n = 10 is not an integer success count divided by 10. The lower-level denominator or repeated-run procedure is therefore unclear.

Metric descriptions: §4.3. Persona scores and n: Appendix Tables 3–5.

Task–persona trade-off

Small headline differences

PC leads all persona metrics. TF leads TSR. The paper reports no confidence intervals or significance tests, so the stability of these differences is unknown.

Efficiency

Humans use fewer steps

Human trajectories require 62.5% fewer steps than TF, the shortest agent policy. Step variability increases in the order TF, PA, PC.

Heterogeneity

Persona results differ

Quality-Focused has PFS 0.908–0.969 but path consistency 0.492–0.569. Urgent Task Finisher PFS rises from 0.143 under TF to 0.429 under PA.

The top-five-persona analysis covers 174 of 240 tasks (72.5%). The paper reports that Eco-Aware Minimalist has mean 0.860 overall and 0.878 with PC. Health-Conscious Explorer has PQA 1.000 under all policies, but n = 3.

Headline scores: Table 1 and §5.1. Persona analysis: §5.2. Steps: §5.3.

What the evidence does not establish

Limits and one documentation inconsistency

Limits stated by the authors

  • The ten personas may not cover real shopping behavior.
  • The task distribution is uneven. Three personas have only 1–4 tasks.
  • An LLM judge can add bias to persona-alignment scores.

§7, Limitations.

Details needed for replication

  • Judge model, prompt, rubric, and score scale
  • Trial count, sampling settings, and random seeds
  • Uncertainty or significance tests
  • Rule for “acceptable equivalent” and raw evaluation denominator
  • Public dataset or code location

The paper does not report these items in its ten pages.

Policy description conflict. §4.2 says PA has no procedural rules and PC adds persona-specific operational rules. Appendix B.2, however, lists concrete PA adaptations such as price sorting and 10–20% budget flexibility. Appendix B.3 mostly lists generic action, cart, budget, and availability rules. This makes the exact treatment difference hard to reconstruct from the paper alone.

Reading

What ShopperBench supports

The study supports a narrow conclusion: with Claude Haiku 4.5 in this 240-task simulated benchmark, stronger persona prompting improves the reported persona scores and adds interaction steps. It does not yet show that these policies generalize to live stores, new models, or real users. The missing judge and run details also prevent an independent reconstruction of the score generation process.
