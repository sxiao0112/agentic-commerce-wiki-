DeepShop: A Benchmark for Deep Research Shopping Agents

DeepShop tests whether an agent can find a product that satisfies several requirements on a live shopping website. Its main result is sobering: the best reported holistic success rate is 32% for a web agent, while two commercial deep research systems each reach 30% on a smaller sample.

Lyu et al.arXiv:2506.02839v13 June 2025Benchmark and dataset150 evaluated tasks

AbstractFull textPDFOfficial code and data repositoryDataset

Question

Can current web agents satisfy diverse, complex shopping requests on live websites? The paper also asks how results change by product category and by query complexity.

Terms in this paper

Product attribute

A feature of the item, such as brand, model, color, size, weight, price range, or a special feature.

Search filter

A constraint such as minimum rating, review count, delivery, release date, return policy, or warranty.

Sorting preference

The requested order of results, such as lowest price, highest rating, newest arrival, or best seller.

Holistic success

A task succeeds only when every requirement that appears in the query succeeds.

Exact task and setup

Agent input
One natural-language shopping query tied to an e-commerce website.
Agent work
Observe the live desktop website, take browser actions, and return a final product answer. The formal model is a partially observable Markov decision process.
Query pool
The authors manually select 50 seed queries from Mind2Web-Live and WebVoyager: 4 Books, 14 Electronics, 20 Home, 5 Fashion, and 7 Sports. GPT-4o first creates one diversity-evolved query per seed. It then applies five rounds of random attribute, filter, or sorting evolution to the 100 queries, producing 600 queries.
Evaluation set
The authors select and manually verify 150 tasks from the 600-query pool, with 30 tasks in each of the five categories. They confirm that an answer is available on the corresponding website.
Difficulty
Easy means 0–1 complexity evolutions; medium means 2–3; hard means 4–5.
Run limits
Each open-source web agent gets at most 15 steps. All four use gpt-4o-2024-08-06. Agent-E, SeeAct, and Browser Use run through Playwright; WebVoyager uses Selenium.

Documented evaluation flow

  1. Give the taskOne shopping query and its target live website.
  2. Run the methodRAG retrieves one page, a web agent acts for up to 15 steps, or a deep research system returns a report.
  3. Split requirementsSeparate the query into attribute, filter, and sorting subqueries.
  4. Judge each partGPT-4o judges web-agent traces; humans judge deep research outputs. Each present part is success or failure.
  5. Compute successReport each part over eligible tasks. Mark the whole task successful only if all present parts succeed.

The 30-query commercial-system results are not measured on the full 150-task set. The paper does not say that the same 30 queries were used for both systems.

Metrics and denominators

For dimension d (attribute, filter, or sorting), let Ed be the tasks that explicitly contain that requirement, and let Ii,d be 1 when the judge says “Success” and 0 otherwise.

dimension success rate = 100 × Σ Ii,d / |Ed|

A missing subquery is skipped. Therefore, it is not part of that dimension’s denominator. The paper does not publish the exact values of |Ed|.

task success rate = 100 × successful complete tasks / all evaluated tasks

A complete task succeeds only if all requirements that are present succeed. A missing dimension is treated as satisfied. The task-success denominator is 150 for Simple RAG and each web agent, and 30 for each deep research system.

For web-agent traces, the evaluator is gpt-4o-2024-08-06 at temperature 0. It receives the subqueries, action history, final answer, and at most 15 screenshots. For deep research systems, humans inspect the result and may use Amazon to verify links.

Judge check. One human annotator independently labels 50 randomly sampled WebVoyager trajectories. Human–GPT-4o agreement is 84% for attributes, 80% for filters, 82% for sorting, and 86% for overall task success. Agreement is the fraction of matching labels. This is agreement, not accuracy against an independent gold answer.

Interaction helps, but completion stays low

Browser Use reaches 32% task success, compared with 7.33% for Simple RAG. A paired t-test reported in Appendix A.3 finds Browser Use higher than Simple RAG and the other web-agent baselines at p<0.05.

Partial success does not ensure task success

SeeAct reaches 52% attribute success but only 10.67% complete-task success. Both deep research systems reach 30% complete-task success despite stronger scores on individual dimensions.

Complexity reduces success

Simple RAG falls from 16% task success on easy queries to 6% on medium and 0% on hard. The mean across web agents falls from 28.5% to 17% to 10%. OpenAI Deep Research reaches 20% on the hard subset.

Visual categories expose failures

Simple RAG scores 0% task success in Fashion and Sports. Gemini scores 0% in Sports, and OpenAI scores 0% in Fashion and Sports. The paper reports these category results in Figure 5a.

What is new

The distinct contribution is an online shopping benchmark that combines three kinds of requirements in the same task: item attributes, filters that may require interface actions or product-page checks, and requested sorting. It also reports both component-level and all-requirements success. The data-generation method expands 50 real benchmark queries into a 600-query pool, then uses a balanced, manually verified 150-task evaluation subset.

Limits and reading cautions

  • The benchmark uses live websites. Content and interfaces can change, so exact reruns may face a different environment.
  • The balanced set has 30 tasks per category. The authors state that this does not represent real shopping-query frequency.
  • The benchmark covers desktop, English, single-turn tasks. It excludes mobile layouts, multilingual requests, changing user intent, and user feedback trajectories.
  • GPT-4o creates the evolved queries and also judges the open-source agents. The 50-trajectory check measures agreement with one human annotator.
  • The paper omits each fine metric’s eligible-task count. Rounded percentages cannot replace those unpublished denominators.
  • Commercial systems use 30 queries and human evaluation, while the other methods use 150 tasks and GPT-4o evaluation. Their rows are therefore not a controlled like-for-like comparison.
  • The reported error examples support failure categories such as poor grounding, weak replanning, limited browser actions, repeated mistakes, and incorrect links. They do not give prevalence estimates for these error types.
