Agent Security and Prompt Injection

Agents read external content and use tools. An attacker can place instructions in that content. The agent can then follow the attacker’s goal instead of the user’s goal.

What this topic covers

Indirect prompt injection is an instruction in third-party content, such as a webpage or email. The instruction tries to change the agent’s behavior. It can redirect a task or cause an unauthorized action.

This topic also covers two related risks. An attacker can promote chosen content in a retrieval system. An agent can also act deceptively because of its own incentives. These risks need different tests and controls.

How defenses are evaluated

Li et al. (2026) evaluate prompt injection defenses with three measures:

  • Benign utility: The agent completes the task when no attack is present.
  • Utility under attack: The agent completes the user’s task when an attack is present.
  • Attack success rate: The attacker’s goal succeeds.

A defense can stop attacks and still be unusable. This occurs when the defense also blocks helpful external instructions. AgentDyn calls this problem overdefense.

Four defense types

  • Prompting defenses mark untrusted content or repeat trusted instructions.
  • Filtering defenses use a detector to find suspected injections.
  • Alignment defenses train the model to give priority to the user’s instruction.
  • System defenses restrict tools, privileges, or information flows.

What the papers found

AgentDyn: defenses lose security or utility on harder tasks

AgentDyn contains 60 open-ended tasks and 560 injection test cases. The tasks cover Shopping, GitHub, and Daily Life. They require dynamic planning and include helpful third-party instructions.

The authors evaluate ten defenses on twelve agents. They report that almost all defenses are either not secure enough or cause significant overdefense. This result applies to AgentDyn. It does not prove performance in all deployed systems.

AgentDyn is more demanding than the benchmarks that the authors compare against. It still has limits. It includes three task suites and cannot reproduce the full range of real environments.

GASLITE: a small number of passages can change retrieval results

Ben-Tov and Sharif (2025) study corpus poisoning in dense retrieval. Their attack inserts crafted passages into a corpus. It does not retrain or modify the retrieval model.

The authors test nine dense retrievers. For concept-specific queries, a poisoning rate of at most 0.0001% makes adversarial passages appear in the top ten results for 61% to 100% of unseen queries against most tested models.

Evidence boundary: GASLITE measures content promotion in retrieval. It does not measure whether an agent follows a prompt injection in the retrieved passage. The result identifies a possible exposure channel, not a complete prompt injection attack.

Linear probes: deception signals do not transfer reliably across model families

Sims (2026) trains linear classifiers on model activations. The study uses three instruction-tuned models in three commercial negotiation scenarios.

At the best tested layer, the probes reach an area under the receiver operating characteristic curve above 0.93 in 11 of 12 model and scenario combinations. Probes trained on instructed deception detect incentive-driven deception in the same model with values from 0.70 to 0.77.

Transfer between model families is weak. Tests between Llama and Mistral produce values from 0.51 to 0.56. A monitor therefore needs validation for each architecture.

Evidence boundary: The study finds a correlation between activations and labeled deception. It does not show that steering the activation direction changes deceptive behavior in generated text. The study also does not test prompt injection.

What the evidence means

  • Evaluate security and task completion together.
  • Include helpful external instructions in prompt injection tests.
  • Test retrieval separately from the agent’s response to retrieved content.
  • Validate activation monitors on the model family and setting where they will run.
  • State the tested scope before you apply a result to a deployed system.

Open questions

  • How well do prompt injection defenses work in longer tasks and more varied applications?
  • Can evaluations use stronger attacks without creating unrealistic threat models?
  • Which controls stop corpus poisoning in proprietary and larger retrieval systems?
  • Can activation monitors predict deceptive behavior outside commercial negotiation?
  • Can researchers show that an activation intervention changes generated behavior?
